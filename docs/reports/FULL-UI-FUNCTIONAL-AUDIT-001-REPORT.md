1. Tickets page: button "Открыть" could appear non-functional when detail API response was unavailable.

   - Fix: added automation suggestions block (runbooks and matched rules) to the ticket details modal.
   - File: frontend/src/pages/TicketsPage.tsx

3. Automation page: mutation actions had weak user-visible error feedback.
   - Fix: added centralized `actionError` banner + onError handlers for key mutations.
   - File: frontend/src/pages/AutomationPage.tsx

4. Automation page: execution controls lacked explicit step update action.
   - Fix: added "Update Step" action and expanded execution patch payload support.
   - File: frontend/src/pages/AutomationPage.tsx

5. Frontend routing edge case for `/assets` path under nginx SPA hosting.
   - Fix: updated nginx `try_files` strategy and explicit `/assets` handling to avoid route collisions with static bundle directory.
   - File: frontend/nginx.conf

## Environment Limitation

Integrated browser automation showed intermittent navigation instability specifically when probing `/assets` route (`ERR_CONNECTION_REFUSED` in the tool context) despite successful direct HTTP checks (`/assets` returns 200) and normal app/backend traffic. This is treated as a tooling/runtime artifact rather than application-level failure.

## Residual Risks

- `/assets/` (with trailing slash) now returns 404 by design to prevent static-directory collision with SPA route `/assets`.
- If strict support for both `/assets` and `/assets/` is required, add explicit normalization/redirect handling while preserving static bundle serving semantics.
