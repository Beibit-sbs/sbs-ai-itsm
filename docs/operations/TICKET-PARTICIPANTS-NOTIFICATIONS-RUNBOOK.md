# Участники, наблюдатели и персональные уведомления

Дата: 2026-08-14  
Миграция: `20260814_0079`

## Назначение

Модуль позволяет подключать к заявке дополнительных специалистов,
представителей заявителя и наблюдателей, не меняя основного исполнителя.
Каждый участник получает только выбранные события и каналы уведомлений.

## Как подписаться на свою заявку

1. Откройте **Инциденты** и нужную заявку.
2. Перейдите на вкладку **Участники**.
3. Выберите область событий:
   - **Все события, включая внутренние** — только для сотрудников с доступом;
   - **Публичные обновления** — безопасный режим по умолчанию;
   - **Только изменение статуса**;
   - **Не уведомлять**.
4. Выберите каналы **Внутри системы** и/или **По электронной почте**.
5. Нажмите **Наблюдать за заявкой** или **Сохранить настройки**.

Пользователь может изменять и удалять только собственную подписку. Для
управления другими участниками требуется `tickets.participants.manage`.

## Как добавить участника сотруднику Service Desk

1. Откройте вкладку **Участники** в карточке заявки.
2. Выберите активного пользователя организации или заполните имя и email
   внешнего участника.
3. Укажите роль: `WATCHER`, `COLLABORATOR` или
   `REQUESTER_REPRESENTATIVE`.
4. Настройте область событий и каналы.
5. Обязательно укажите причину длиной не менее трёх символов.
6. Нажмите **Добавить участника**.

Повторное добавление активной записи блокируется `HTTP 409`. Удаление является
мягким: сохраняются причина, автор, время, ticket history и audit event.

## Правила приватности

- Внутренний комментарий никогда не отправляется заявителю.
- Участник с `PUBLIC_ONLY` не получает внутренние комментарии.
- `STATUS_ONLY` получает только назначение, смену статуса, решение и SLA-события.
- Внутрисистемное уведомление создаётся только для участника с локальной
  учётной записью; внешний участник может использовать email.
- Notification Center по умолчанию показывает только уведомления текущего
  получателя. Просмотр организации требует `notifications.manage` и параметр
  `scope=tenant`.
- Пользователь не может отметить прочитанным чужое уведомление; API возвращает
  `HTTP 404`, не раскрывая факт его существования.

## Permissions

| Permission | Назначение |
|---|---|
| `tickets.participants.read` | видеть участников доступной заявки |
| `tickets.participants.manage` | добавлять и изменять любых участников |
| `tickets.watch` | управлять собственной подпиской |
| `notifications.read` | читать личный Notification Center |
| `notifications.update` | отмечать личные уведомления прочитанными |
| `notifications.manage` | запрашивать tenant-wide operational view |

Стандартные роли backfill-ятся идемпотентно: organization admin, IT manager и
IT agent получают чтение/подписку; admin/manager/agent получают управление;
requester получает чтение и собственную подписку.

## Диагностика

- Нет вкладки **Участники**: проверить `tickets.participants.read` в `/auth/me`.
- Нет формы добавления: требуется `tickets.participants.manage`.
- Уведомление не пришло: проверить `notification_scope`, флаги каналов,
  активность участника и тип события; для внешнего участника нужен email-канал.
- `409 Participant was changed`: обновить карточку и повторить изменение на
  актуальной `version_number`.
- Readiness показывает `migrations: out_of_date`: убедиться, что образ сервиса
  `migrate` собран из той же ревизии, затем выполнить `alembic upgrade head`.
